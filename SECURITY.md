# Security and support

Run audits on a machine authorized to read the selected exports. Prefer reporting a synthetic example that reproduces the behavior. Public issue reports should omit real webhook payloads, private IDs, authentication headers, signing secrets and customer information.

For sensitive findings use the repository's private vulnerability reporting channel when enabled. Keep only a non-sensitive contact request in a public issue if that channel is unavailable. File and memory limits and the input trust model are described in the README.
